# Циферки

Веб-сервис количественного анализа для исследователей. Загружаете данные — получаете расчёт, проверку допущений и пошаговое объяснение методологии: что, почему и как было посчитано.

## Текущее состояние

- **v0.1 (прототип)** — t-тест для независимых выборок. Работает на `http://72.56.242.246:8080` (systemd + nginx).
- **v0.2 (в разработке)** — модульное приложение по ТЗ (`docs/ТЗ.md`). Работает на `http://72.56.242.246:8081` (Docker Compose).

## Возможности v0.2

- Вход по логину для участников, архив загрузок (кто и когда загрузил), управление пользователями.
- Поток работы: проект (название) → файлы (основной / демография / предыдущая волна) → задача → результат; история шагов с возвратом к промежуточным состояниям.
- Разбор выгрузок: форматы report («N. Matrix, …», «N. Choice – …») и base (коды/ответы, `q9_r1`), автоопределение шапки и начала данных, типы колонок, шкалы согласия (включая формы «(на)») и «про меня», «Затрудняюсь ответить» как пропуск.
- Мэтчинг файлов по ID между платформами (опция «только complete»), фильтры выборки.
- **Top2% и нормы**: доля верхних 2 категорий шкалы, 95% интервал Уилсона, сравнение с нормой (Q3 по концептам, медиана, фиксированная вручную, пул волн), флаги «выше / ниже / не значимо».
- **Сравнение волн**: полные выборки (z-тест долей), панель (одни и те же респонденты, критерий МакНемара), панель с окном по времени между волнами; предупреждения о несопоставимых метриках.
- **Экспорт Excel с формулами** (COUNT, COUNTIF, QUARTILE.INC, MEDIAN, ДИ Уилсона, NORM.S.DIST, CHISQ.DIST.RT) — не «мёртвые» значения, а живые расчёты.

## Структура v0.2

    backend/   — FastAPI: авторизация, архив загрузок, модули анализа
    frontend/  — React + Vite + AG Grid (интерфейс)

Локальный запуск для разработки:

    cd backend && uvicorn app.main:app --reload     # API на 127.0.0.1:8000
    cd frontend && npm install && npm run dev       # интерфейс на 127.0.0.1:5173

Деплой: workflow **Deploy to server** в GitHub Actions (нужны секреты `SERVER_HOST`, `SERVER_PASSWORD`, `ADMIN_PASSWORD`).

## Возможности (v0.1)

- Загрузка данных: CSV, Excel (.xlsx)
- t-тест для независимых выборок — полная процедура:
  1. описательные статистики по группам;
  2. проверка нормальности в каждой группе (Шапиро–Уилк);
  3. проверка однородности дисперсий (Левен по медиане / Браун–Форсайт);
  4. автоматический выбор теста: Стьюдент / Уэлч / Манн–Уитни;
  5. размер эффекта: d Коэна, g Хеджеса, рангово-бисериальная корреляция;
  6. вывод с обоснованием каждого решения (блок «Как это считалось»).

## Локальный запуск (по желанию, для проверки)

Требуется Python 3.10+.

    python -m venv .venv
    .venv\Scripts\activate        # Windows
    source .venv/bin/activate     # Linux/macOS

    pip install -r requirements.txt
    uvicorn app.main:app --reload

Открыть: http://127.0.0.1:8000

## Развёртывание на сервере (один раз)

Предполагается Ubuntu/Debian и SSH-доступ. В SSH-сессии:

    sudo apt update && sudo apt install -y git
    sudo git clone https://github.com/XandriaF/ciferki.git /opt/ciferki
    sudo bash /opt/ciferki/deploy/setup.sh ваш-домен.ru

Если домена нет — запустите без аргумента (сервис будет доступен по адресу http://IP:8080):

    sudo bash /opt/ciferki/deploy/setup.sh

Скрипт сам установит nginx и Python-окружение, настроит автозапуск (systemd) и покажет статус.

HTTPS (если есть домен, направленный на сервер):

    sudo apt install -y certbot python3-certbot-nginx
    sudo certbot --nginx -d ваш-домен.ru

Проверка: `curl http://127.0.0.1:8000/health` → `{"status":"ok"}`.

## Как обновлять сервис

1. Вносите изменения локально (через opencode/Claude) в папку проекта.
2. Отправляете изменения на GitHub (GitHub Desktop или веб-интерфейс).
3. На сервере в SSH-сессии:

    sudo bash /opt/ciferki/deploy/update.sh

Скрипт сделает `git pull`, обновит зависимости и перезапустит сервис.

## Обновление через GitHub (без терминала)

1. Изменения загружаются в репозиторий (обычный push).
2. На странице **github.com/XandriaF/ciferki/actions** выберите workflow **Deploy to server** → **Run workflow**.
3. Через 1–2 минуты сервис обновится: `git pull`, зависимости и перезапуск выполняются автоматически.

Для этого в настройках репозитория (Settings → Secrets and variables → Actions) должны быть секреты `SERVER_HOST` и `SERVER_PASSWORD`.

## Как добавить новый тест (стандарт)

Каждая процедура оформляется одинаково — это и есть прозрачность:

1. `app/analysis/<тест>.py` — функция `run(df, ...) -> dict`, возвращающая:
   - `procedure.steps` — пошаговый ход анализа и принятые решения;
   - `assumptions` — проверки допущений;
   - `primary` — основной результат, `reference` — справочный (если нужен);
   - `conclusion` — текстовый вывод для исследователя.
2. Роут в `app/main.py` (по образцу `/api/ttest`).
3. Форма в `app/static/index.html` и рендер в `app/static/app.js` (по образцу t-теста).
